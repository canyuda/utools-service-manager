# Windows 服务管理 uTools 插件 — 界面设计文档

- 日期：2026-09-23
- 状态：设计稿（待评审，未开始实现）
- 参考文档：https://next.u-tools.cn/docs/（Runtime：Electron 34.5.8 / Chromium 132 / Node 20.19.1）

## 1. 背景与目标

做一个 uTools 插件，管理用户**指定的少量 Windows 服务**（如 Redis、Consul、nginx 这类自建服务），提供：

1. 修改"启动类型"：自动 / 自动(延迟启动) / 手动 / 禁用
2. 服务实时状态展示（免打开 services.msc）
3. 服务状态变更：启动、停止、暂停、恢复、重新启动

非目标（本期不做）：服务新建/删除、依赖管理、远程管理、非 Windows 平台。

## 2. 入口与生命周期

- `plugin.json` features：`cmds: ["服务管理", "服务", "services", "svc"]`（≤5 个，自动支持拼音/首字母），`platform: "win32"`。
- `onPluginEnter`：读取已添加服务列表（`utools.dbStorage`），立即拉取一次全量状态后开始轮询。
- `onPluginOut`：停止轮询定时器（BrowserView 退后台会被移除，必须清理）。
- 窗口：使用默认高度 544（`pluginSetting.height`），列表超长时内部滚动，不动态调高度。

## 3. 信息架构

单页应用，两个视图切换，无多级页面（uTools 窗口窄，保持一屏内完成操作）：

```
V1 我的服务（默认） ⇄ V2 添加服务
```

- **V1 我的服务**：用户白名单内的服务卡片列表 + 实时状态 + 行内展开详情（含启动类型修改、全部操作按钮）。
- **V2 添加服务**：全系统服务搜索列表，勾选加入"我的服务"。

## 5. 状态展示设计

### 5.1 服务运行状态徽章

| 状态 | 圆点/徽章 | 颜色（亮色模式） | 附加表现 |
|---|---|---|---|
| Running 运行中 | ● 实心 | 绿 `#34c77b` | — |
| Stopped 已停止 | ○ 空心 | 灰 `#909399` | — |
| Paused 已暂停 | ◐ 半实心 | 黄 `#e6a23c` | — |
| StartPending / StopPending 启停中 | ● 脉冲闪烁 | 蓝 `#409eff` | 行内所有按钮禁用 |
| Unknown / 查询失败 | ✕ | 红 `#f56c6c` | 状态文字显示错误原因 |
| 服务不存在（被卸载） | ✕ | 红 | 行尾提示"服务不存在，点击移除" |

第二行文字与徽章联动：`Running`/`Stopped`/`Paused`/`正在启动…`/`正在停止…`。

### 5.2 实时刷新机制（UI 层约定）

- 进入插件立即查一次，之后 **2s 轮询**；`onPluginOut` 时清除定时器。
- 状态值**与上次不同**时：圆点和状态文字做一次 600ms 高亮闪烁动画，提示"刚刚发生了变化"。
- 顶部筛选栏右侧显示刷新指示（⟳ 旋转一次/每轮询周期），鼠标悬停显示"每 2 秒自动刷新"，点击可立即手动刷新。
- 单次轮询中某个服务查询失败（如被卸载）不影响其他服务，该行显示 Unknown。
- 操作进行中（启动/停止点击后）：对应行按钮全部进入 loading/禁用，状态列显示 Pending 徽章，直到轮询确认状态落地或超时（15s，超时后恢复按钮并 toast 错误）。

### 5.3 启动类型标签

右侧常显，四个取值统一小标签样式：

- 自动：蓝边蓝字 · 自动(延迟启动)：蓝边蓝字 + `⏱` 前缀 · 手动：灰边灰字 · 禁用：红边红字
- 点击标签 = 展开详情面板（快捷入口），不直接弹菜单，避免误触。

## 6. 操作按钮可用性矩阵

按钮组统一为五个：启动 ▶ / 停止 ■ / 暂停 ⏸ / 恢复 ⏵ / 重启 ↻。
**策略：不合法的操作直接不渲染**（收起态快捷按钮区空间有限）；展开详情面板内五个按钮全渲染、不合法的置灰。

| 当前状态 | 启动 | 停止 | 暂停¹ | 恢复 | 重启 |
|---|---|---|---|---|---|
| Stopped | ✅ | — | — | — | — |
| Running | — | ✅ | ✅(若支持) | — | ✅ |
| Paused | — | ✅ | — | ✅ | ✅ |
| StartPending / StopPending | 全部禁用 | | | | |

¹ 仅当服务查询结果里带 `ACCEPTS_PAUSABLE` 控制接受位时显示"暂停"；不支持暂停的服务（大多数）Running 态只出现"停止/重启"。

- **重启** = 停止 → 轮询等待 Stopped（≤15s）→ 启动，UI 全程 Pending 徽章；Paused 状态下重启先恢复再走停止流程（或直接停止），按 PowerShell `Restart-Service -Force` 语义。
- 所有写操作点击后立即置灰本行全部按钮，防止连点。

## 7. 反馈与错误处理

### 7.1 操作反馈

- 成功：右下角轻 toast（2s 自动消失）：`已启动 Redis`。
- 失败：错误 toast 常驻 6s + 可展开"详情"查看原始错误码。

### 7.2 错误码 → 人话映射表

| 错误码 | 含义 | UI 文案 |
|---|---|---|
| 5 | 拒绝访问 | 权限不足：请以管理员身份运行 uTools 后重试（见顶部横幅） |
| 1053 | 服务未及时响应启动/停止 | 服务响应超时，请到 services.msc 检查 |
| 1051 | 存在依赖服务 | 该服务正被其他服务依赖，停止失败：xxx |
| 1056 | 服务已在运行 | 服务已在运行中，无需启动 |
| 1062 | 服务未启动 | 服务当前未运行，无法执行该操作 |
| 1060 | 服务未安装 | 服务不存在，可能已被卸载 |

### 7.3 管理员权限横幅

- 进入插件时 preload 检测一次是否管理员（`net session` 是否报拒绝访问）。
- 非管理员：顶部黄色横幅，两个动作：`[ 以管理员身份重启 uTools ]`（推荐，一次搞定）/ `[ 了解更多 ]`（展开说明：也可保持现状，每次写操作会弹 UAC 窗口单独授权）。
- 管理员：横幅不显示。
- 只读操作（状态轮询、列表查询）不需要管理员权限，非管理员状态下**状态展示完全可用**。

## 8. 排序与筛选

- 筛选：全部 / 运行中 / 已停止 / 已暂停，tab 上带计数徽标。
- 排序：默认按添加顺序（用户心智：我加的顺序）；详情面板内不做全局排序设置，保持简单。
- 移除服务：详情面板"从列表移除"→ 确认弹窗（只从插件列表移除，不动服务本身，文案明确）。

## 9. 视觉规范

- **主题跟随 uTools**：`utools.isDarkColors()` 判断深浅色，两套色板变量（CSS custom properties）。
- 字体：系统默认（`-apple-system, "Microsoft YaHei", sans-serif`），显示名 14px/600，辅助信息 12px/400，行内按钮 12px。
- 间距：行内边距 12px，卡片间距 8px，详情面板内 16px 栅格。
- 状态色板见 §5.1；操作按钮：启动=绿系、停止/禁用类=红系、暂停/恢复=黄系、重启=蓝系，均为描边按钮（非实心），危险操作（停止、禁用类型变更、移除）文案红。
- 窗口宽度自适应（uTools 窗口较窄），列表区 `overflow-y: auto`，滚动条样式跟随系统。

## 10. UI → 技术映射（可行性速查）

| UI 元素 | 数据/命令（preload 内执行） |
|---|---|
| 我的服务列表、状态轮询 | `sc.exe query <name>` 或一次性 `Get-Service -Name a,b,c`（2s 周期） |
| 详情基本信息 | `sc.exe qc <name>`（启动类型/二进制/账户）+ `Get-Service` Description |
| 启动类型修改 | `sc.exe config <name> start= auto\|delayed-auto\|demand\|disabled` |
| 启动/停止/暂停/恢复 | `sc.exe start\|stop\|pause\|continue <name>`（或 PowerShell `Start/Stop/Suspend/Resume-Service`） |
| 重启 | `Restart-Service -Name <name> -Force` |
| 暂停能力判断 | `sc.exe query <name>` 输出中的 `ACCEPTS_PAUSABLE` 标志 |
| 全量服务列表（V2） | `Get-Service` 全量 + `sc.exe qc` 惰性补详情 |
| 白名单持久化 | `utools.dbStorage.setItem('svc_list', [...])` |
| 管理员检测 | `net session` 退出码 |
| MCP 工具 | `plugin.json` 的 `tools` 声明 + `utools.registerTool()` 注册（§12） |
| 需要提权的单次操作（备选） | `Start-Process -Verb RunAs -Wait powershell -Argument ...` 触发 UAC |

约定：所有 `sc` 一律写全 `sc.exe`（PowerShell 下 `sc` 是 Set-Content 别名）；服务名全部加引号（防空格与特殊字符）；轮询在 preload 中做，UI 只消费 `window.svcApi.*` 暴露的 Promise 接口。

## 12. MCP 集成（AI Agent 直接控制服务）

目标：在 Claude Code / Codex / WorkBuddy 等 AI Agent 里，通过 uTools 的 MCP Server 直接查询并操作本插件管理的服务（启停、改启动类型）。

依据 uTools 官方机制（[MCP 集成文档](https://next.u-tools.cn/docs/development/mcp.html)）：

- uTools 内置 MCP Server，用户需在 **uTools 设置 → AI 设置 → MCP 服务** 中开启，Agent 才能发现并调用工具。
- 插件在 `plugin.json` 的 `tools` 字段声明工具：`description` 必填且要准确（Agent 靠它判断何时调用）、`inputSchema` 必填且为合法 JSON Schema（无参用 `{ "type": "object", "additionalProperties": false }`）、`outputSchema` 可选；工具名小写 snake_case 且唯一。
- 执行逻辑通过 `utools.registerTool()` 注册，名称必须与声明一致；**插件未运行时 uTools 会自动拉起插件完成工具初始化**（即 Agent 调用不依赖插件窗口是否打开）。

### 12.1 工具清单

| 工具名 | 入参 | 风险级 | 说明 |
|---|---|---|---|
| `list_managed_services` | 无 | 只读 | 白名单服务及实时状态 |
| `search_services` | `{ query }` | 只读 | 全量服务搜索（按服务名/显示名） |
| `get_service_detail` | `{ name }` | 只读 | 详情：状态/启动类型/二进制/账户 |
| `start_service` | `{ name }` | 写 | 启动 |
| `stop_service` | `{ name }` | 写 | 停止 |
| `restart_service` | `{ name }` | 写 | 重启（停止 → 等待落定 → 启动） |
| `pause_service` / `resume_service` | `{ name }` | 写 | 暂停/恢复（仅支持暂停的服务） |
| `set_service_start_type` | `{ name, startType }` | 写 | `auto` / `delayed-auto` / `demand` / `disabled` |

统一返回 JSON：`{ ok, service, state?, startType?, errorCode?, message }`，`errorCode` 复用 §7.2 映射，Agent 拿到的是可直接转述给用户的结构化结果。

### 12.2 安全设计（写操作四道闸）

Agent 能直接启停系统服务，属高危能力，设计上层层设闸：

1. **MCP 总开关默认关闭**：插件设置页手动开启（§12.3）。关闭时所有写工具直接返回 `{ ok:false, errorCode:'MCP_DISABLED', message:'Agent 控制未开启，请在插件设置中开启' }`；只读工具同样受此开关约束。
2. **风险分级**：开启总开关后，写操作（启停/改启动类型）另需"允许 Agent 写操作"子开关，默认关闭。
3. **权限同 UI**：写工具复用管理员检测与 §7.2 错误映射；非管理员时返回错误码 5 的人话提示，引导用户以管理员身份重启 uTools。
4. **审计日志**：每次工具调用记录到 `utools.dbStorage`（时间/工具名/入参/结果，保留最近 50 条），插件设置页可查看、可清空——同时回答了 §11 待定问题 3。

### 12.3 UI 改动

- 顶部栏新增 **⚙ 设置** 入口 → 设置弹层，包含：MCP 总开关、允许 Agent 写操作子开关、审计日志列表、轮询间隔、UAC 策略说明。
- `onPluginReady` 中完成 `utools.registerTool()` 注册；工具处理器内部**复用与 UI 相同的服务控制层**（同一套 sc.exe/PowerShell 封装），不另造逻辑，保证错误映射、超时、Pending 处理一致。

### 12.4 Agent 侧接入示例（Claude Code）

uTools 的 MCP Server 开启后，Agent 以标准 MCP 协议连接即可（无需为每个插件单独配置）：

```
# Claude Code 侧（示意）
mcp__utools__list_managed_services  →  返回白名单服务状态
```
